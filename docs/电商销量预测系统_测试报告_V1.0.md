> 🔒 **运行纪律（本轮发现，已写入每个脚本的文件头）**：
> 平台的批量删除保护按「**单次工具调用的累计删除数**」计数（阈值 50）。
> 一条命令里 for 循环串跑多个校验脚本会让前面脚本的临时目录清理量
> 累积到后面脚本头上，被判为批量删除后脚本**直接退出**，日志只留一行
> `STATUS: FAILED` —— 看起来像代码缺陷，实际是平台的保护机制。
> 故：**每个校验脚本单独占一条命令**。

### 1.4 浏览器工具链：本机只有 Edge，怎么跑满三款内核

`DOD-EP9` 要求四浏览器。本机只有系统自带的 Edge，缺的两款按下面的方式补齐
（**全部解包到工作区 `data/tmp/browsers/`，不写注册表、不建快捷方式、不污染系统**）：

| 浏览器 | 获取方式 | 体积 |
|---|---|---|
| Chrome | npmmirror 的 `chrome-for-testing` 镜像 —— 官方为**测试**发布的独立二进制、原生支持 CDP，解压即用 | 下载 207 MB / 解压 438 MB |
| Firefox | npmmirror 的官方 `Firefox Setup 157.0.1.msi` → **7-Zip 两层展开**（见下） | 下载 92 MB / 解压 350 MB |
| Safari | —— | ❌ 无法获取：Windows 平台无 Safari 发行版 |

> 🔴 **Firefox 便携化的坑**：官方 MSI 其实是个 **wrapper**，真正的安装器在内嵌的
> `Binary.WrappedExe`（93 MB）里，产品文件一个都没有。`msiexec /a`（管理员安装）
> 在这种结构下**解不出任何文件** —— 只会把 msi 自己复制到 `TARGETDIR`，
> 而**日志与退出码仍返回 0**，极具迷惑性。可行路径是 7-Zip 两层展开：
> `7z x "<msi>"` → 得 `Binary.WrappedExe` → `7z x Binary.WrappedExe` → 得 `core/firefox.exe`。
> （本机 npm 镜像若不可达，Chrome/Firefox 的版本号取自 `chrome-for-testing` 的
> `last-known-good-versions.json` 与 Mozilla `latest` 重定向，均**联网核过**。）
