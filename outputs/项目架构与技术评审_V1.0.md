## 三、强项：面试时应当主动引导去问的地方

这五项是**很难临场编出来的**，务必主动展示：

1. **分层依赖是硬约束，不是口头约定。**
   我用脚本扫了四个方向（`api→dao`、`services→api`、`dao→services`、`algo→services`），结果**全部 0 处违规**。
   > 话术：「我把『DAO 只能被 Service 调用』写成了可执行的红线，改代码前跑一次就知道有没有破。」

2. **并发模型没踩「async def 里跑同步阻塞」的坑。**
   所有阻塞端点都过 `run_in_threadpool`（`predictions.py:109/157/188/219/270`、`admin.py:89…`），代码里还留了注释解释「直接在 async def 里同步调用会占住事件循环，期间连 `/health` 都不响应」。
   > 这是**绝大多数候选人会翻车**的点，能主动讲出来就是加分项。

3. **可观测性做了 request-id 贯穿。**
   `RequestIDMiddleware` + `AccessLogMiddleware` + `ContextVar` 注入日志格式，且注释记录了「包裹顺序反了会导致日志里 request_id 恒为 `-`」这个实测坑。

4. **前端类型纪律极干净。**
   15,523 行里 `any` / `as any` / `@ts-ignore` **全为 0**，`dangerouslySetInnerHTML` **0 处**，全库只有 **1 个** `eslint-disable`（且附了原因）。这在带 ECharts 的项目里很少见——ECharts 的 option 是天然的 `any` 洼地。

5. **「两套数字」被系统性消灭。**
   后端 `cost_model.py` 把耗时预估固化成标定公式，文档里明确写了「为什么不直接用 `eval_report.timing_ms`」；前端 `THRESHOLDS` 是后端 `models/metric.py` 的镜像，且有断言守护。**这是「工程思维」而非「写完就算」的证据。**

## 四、候选人视角：现在最怕被追问的 7 个点

按「被问到的概率 × 答不上来的代价」排序。每条给出**应答策略**。

### ① 「你说导出是流式的，我看这不还是全读进内存了吗？」——🔴 最危险

`prediction_dao.py:168` 的 docstring 写着：

> 🔒 **不返回 list**：上限 300 万行（`DB-T04`），一次性物化会把进程内存打满。这里用 `yield_per` 分批取，CSV **边生成边写出，内存占用与数据量无关**。

但 `result_service.py:654` 的实现是：

```python
buf = io.StringIO()                       # ← 全量累积
writer = csv.writer(buf, lineterminator="\n")
for row in prediction_dao.iter_all_for_export(db, task_id):
    writer.writerow(_export_cells(row))
return buf.getvalue().encode("utf-8-sig")  # ← 再来一份 bytes（峰值 2×）
```

接口层再 `Response(content=...)` 整体驻留；`_persist_export()` 还写第三份。

**后果**：300 万行 × 约 60 B ≈ **180 MB（str）+ 180 MB（bytes）**；并发两次导出在 2 GB 容器里直接 OOM。**DAO 的流式被服务层抵消了。**

> **应答**：不要辩解「DB 那层是流式的」。直接承认这是**分层边界上的失真**——「我在 DAO 做了 `yield_per`，却在 service 用 `StringIO` 收口，等于白做；正确做法是 service 返回生成器 + 接口返回 `StreamingResponse`」。
> 然后补一句加分：「这也是我后来给导出加 `chunk` 参数时该一起改的地方，我漏了端到端验证内存曲线。」

### ② 「CSV 里如果 sku_id 是 `=cmd|'/c calc'!A1`，用户用 Excel 打开会怎样？」——🟠 高

`result_service.py:_export_cells()` 直接写 `p.sku_id` / `p.warehouse_id`，这两个字段**来自用户上传的 CSV**，未做任何前缀转义。

Excel 把以 `=` `+` `-` `@` `\t` `\r` 开头的单元格当公式执行（CSV Injection / DDE）。**这是唯一一处「用户输入 → 文件 → 他人本机执行」的链路**，比 SQL 注入更现实（ORM 已经挡住了后者）。

> **应答**：先讲清链路（上传 → 落库 → 导出 → 别人打开），再说修法（`'` 前缀或 `\t` 前缀 + 只对危险首字符处理，避免污染正常数值列）。**能自己发现这条的人，安全分直接上一档。**

### ③ 「登出之后，我把 Token 拿去用，为什么重启一次又能用了？」——🟠 高

`security.py:72`：

```python
_REVOKED: dict[str, int] = {}     # jti -> exp，纯进程内存
```

Jaeger 说这是进程内存 → **服务重启后所有登出记录清零**，被窃 Token 可以一直用到 `exp`（12 小时）。同理多 worker 之间不共享（所以才有 `workers=1` 铁律）。

> **应答**：「这是我知道的取舍，换来的好处是零依赖、零 IO；代价是重启即失忆。生产形态应落一张 `revoked_tokens(jti PK, exp)` 表 + 定时清理，或换 Redis。」——**能说出代价与迁移路径，比假装没有这个问题强得多。**

### ④ 「`requirements.txt` 里 `pytest==8.3.3`，`package.json` 里 `vitest` + `@testing-library/react`，测试文件在哪？」

**实测：0 个 pytest 文件，0 个 vitest 文件，`package.json` 连 `test` 脚本都没有。**

这是典型的「装了不用」——面试官会直接理解为「凑技术栈」。

> **应答**：**不要说「38 套脚本就是测试」**（会被追问「覆盖率多少 / 怎么 mock DB」）。正确说法：
> 「我的验证是**黑盒可复现断言**，35 个脚本跑真实服务、真实模型、真实浏览器，抓的是端到端不变量（逐位等价、HTTP 码、DOM 断言）。它的**优势**是能抓住单元测试抓不到的集成失真（这次我就在导出上抓到了分层不一致）；**劣势**是慢、需要种子数据、拿不出行覆盖率。**pytest 依赖是我为后续重构留的，还没落地——这条我承认是欠账。**」

### ⑤ 「`dataset_service.py` 1,366 行，`inspect_file()` 一个函数 273 行。为什么不拆？」

> **应答**：「这是全项目最该重构的文件。`inspect_file` 里塞了 7 步校验 + 预览 + 统计，我抽了 7 个 `_step_*` 但没抽成模块。**正确的切法是 `validators/` 子包，每步一个类，返回统一 `ValidationIssue`**，这样第 8 步加进来不用动主流程。」——主动承认 + 给出具体切法，比辩解强。

### ⑥ 「`app/schemas` 为什么用 `importlib.spec_from_file_location` 去加载 `code/backend/schemas.py`？」

这是**全项目最不常规的一处设计**。`app/schemas/__init__.py:44-58` 用 `spec_from_file_location` 按绝对路径加载**包外文件**。

好处（文档里写了）：单一真源，`verify_schemas.py` 与运行期读同一份，避免模型漂移。
代价：**打包/部署必须把整个 `code/` 带走**（我确实因此踩过 `ImportError`）；IDE 跳转与静态分析失效；`pip install` 后不可用。

> **应答**：「动机是消灭『两套模型定义』，这个目标我保住了；但实现方式选错了——应该反向：`app/schemas` 做真源，用脚本**生成** `code/backend/schemas.py` 供文档与校验引用，而不是运行期反向依赖包外文件。」

### ⑦ 「错误全部返回 HTTP 200，你的监控怎么告警？」

`errors.py:129`：`status = 401 if exc.code in _HTTP_401_CODES else 200`。

> **应答**：先讲**动机**（前端只需一套 `body.code` 分支；跨网关/代理时不被中间层改写状态码）——这是真实理由，也是平台网关真出过问题的地方。
> 再讲**代价**（Nginx/ALB/APM 无法按 5xx 告警，必须解析 body；`curl -f` 失效）与**折中**（`code >= 50000` 映射 5xx，业务校验类保持 200）。**承认这是有争议的取舍**，比主张「这样更好」安全。

## 六、按优先级排序的改动建议

### P0 —— 面试前必须做完（合计约 3 小时）

**① 修 R-01：把导出改真流式**

```python
# result_service.py
def iter_csv(db: Session, task_id: int) -> Iterator[bytes]:
    yield "\ufeff".encode("utf-8")                      # BOM 单独先发
    buf = io.StringIO()
    w = csv.writer(buf, lineterminator="\n")
    w.writerow(EXPORT_HEADER)
    for i, row in enumerate(prediction_dao.iter_all_for_export(db, task_id), 1):
        w.writerow(_export_cells(row))
        if i % 2000 == 0:                                # 每 2000 行冲一次
            yield buf.getvalue().encode("utf-8")
            buf.seek(0); buf.truncate()
    if buf.tell():
        yield buf.getvalue().encode("utf-8")
```

接口层改 `StreamingResponse(iter_csv(...), media_type="text/csv")`；`_persist_export` 改成边写边落盘（或干脆去掉——它能带来的好处远小于内存风险）。

**理由**：这是唯一一处「文档承诺 vs 代码实现」的正面冲突。修掉它，④ 的追问就彻底消失；不修，任何一个读代码的面试官都能一票否决你的「工程严谨性」叙事。

**验收**：`tracemalloc` 跑一次 h=30 导出，峰值内存应**不随行数线性增长**（对比修复前记录两组数字）。

**② 修 R-02：CSV 单元格转义**

```python
_DANGEROUS = ("=", "+", "-", "@", "\t", "\r")

def _safe_cell(v: str) -> str:
    return f"'{v}" if v[:1] in _DANGEROUS else v
```

只对 `sku_id` / `warehouse_id` 这两个**文本列**用；数值列不要碰（否则 `-12` 会变成 `'-12` 破坏类型）。

**理由**：成本 10 行，收益是「我主动审计过注入面」。面试官问安全时，这条能顶三个泛泛而谈。

**③ 修 R-04：要么落地测试，要么删掉依赖——不要两头空**

推荐**保留并落地最小可用集**（成本 1.5 小时）：

```python

def test_formula_injection_is_escaped(): ...
def test_missing_actual_writes_empty_not_zero(): ...

```

```python
# tests/test_units.py —— 不碰 DB / 不碰模型

```

```json
"scripts": { "test": "vitest run" }   // 前端同样先补 2–3 个纯函数用例
```

**理由**：面试官不指望你覆盖率 80%，但**「声明了却不写」比「压根没有」更伤**。3–5 个纯函数用例就能让话题从「你为什么没测试」变成「你怎么挑该测什么」——这是主动权的转移。

**④ 修 R-03：把 `jti` 落库（或写清取舍）**

最小改动：`revoked_tokens(jti TEXT PK, exp INTEGER)` + 启动/每 N 次写入清理过期项。成本约 40 分钟。

**如果时间不够**，退一步：在 `security.py` 该字典上方补一段「已知限制」，并同步写进 README 的「已知限制」表——
> **理由**：面试官能接受「我知道但没做」，很难接受「我不知道」。

### 10.2 顺带发现并修掉的第三个缺陷（原报告未覆盖）

### 10.3 修复过程中遇到的三个陷阱（值得复用）

1. 🔴 **`StreamingResponse` 的生成器不能复用请求的 `Session`。**

**R-09 的两个连带修正（不改就会静默降级）：**

1. 🔴 **下载类接口的 5xx 会丢掉业务码。** `fetch`/axios 在 `responseType: 'blob'` 下，
   `error.response.data` 是 **Blob** 而不是 JSON —— 旧代码 `body?.code` 恒为 `undefined`，
   于是 `50002「原始数据文件已丢失，请重新上传」` 会被降级成一句「请求失败（HTTP 500）」，
   用户不知道该重传数据。修法：识别 `Blob` 且 `type` 含 `json` 时 `await blob.text()` 再 `JSON.parse`。
2. 🔴 **拒绝处理器必须改成 `async`。** `Blob.text()` 是异步的；保持同步写法会 `await` 不了，
   只能退回「按 status 猜码」——等于第一条修了也白修。

**R-10 的口径校正（原评审描述不完全准确）：**

> 原文写「首屏多一次 1 MB 请求」。实测：`echarts` 一直挂在结果页的懒加载路由上，
> **`index.html` 从未 preload 过它**（改前改后的 HTML 都只 preload `react`/`antd`）。
> 所以首屏总字节基本没变（569 → 569 kB）。
> 真实收益是**部署间的缓存复用**：业务代码改动时需重新下载的体积
> 从 567.8 kB 降到 **329.1 kB**，四个 vendor 块 hash 不变。
> 如实校正的理由和 §10.3 里那条 SVG MIME 一样：**结论写错了会留在评审记录里**，
> 后面的人会拿它当事实。

**顺带踩到的坑（写进 `vite.config.ts` 注释）：** 第一版 `manualChunks` 用
`return 'vendor'` 兜底全部未点名依赖，立刻出现
`Circular chunk: vendor -> react -> vendor` 与 `vendor -> antd -> vendor`。
原因是 `echarts-for-react`（被塞进 vendor）import react，而 react 通过
`@remix-run/router`（也被塞进 vendor）反向依赖。**循环 chunk 在 Rollup 里只是警告**，
但会在某些加载顺序下触发 `Cannot access 'X' before initialization`（TDZ）。
⇒ 只点名「体量大且边界清晰」的四组，**不设兜底**。
另：Windows 上 Rollup 的模块 id 可能是反斜杠形式，`chunkOf()` 里先 `\` → `/` 再匹配，
否则配置「看起来生效、实际一条都没命中」。

**R-07 为什么必须两层**

单层都不够，理由各自独立：

- **只限成功数** → 挡不住 CPU DoS。`register()` 在入库**之前**算一次 bcrypt（cost 12 ≈ 250 ms），
  一个「邮箱已存在」的失败请求同样要付这笔成本；而失败路径不写 `operation_logs`，
  也就是说**刷失败请求在库里一点痕迹都不留**。
- **只限尝试数（内存）** → 挡不住重启。配额在内存里，等一次发布就清零。
- **把尝试数也落库** → 被刷时审计表先爆，把「消耗算力」升级成「消耗磁盘 + 污染审计」。

所以：**库层管额度（必须抗重启），内存层管速率（必须含失败）**。
`verify_register_rate.py` 的 `T-R05` 用「被拒耗时 × 3 < 正常耗时」把
「判定在 bcrypt 之前」钉成可执行断言 —— 这一条比「有没有调用限流函数」有用得多。
