这是产品的用户界面（前台 11 页 + 管理端 2 页）。 它不直连后端地址：所有请求都以同源 /api/… 发出， 由 Vite 开发服务器代理转发到后端（127.0.0.1:8000）。 因此 前端必须与后端同时运行，否则页面能打开但没有任何数据。

3启动前端

在项目根目录打开一个终端，执行（另一个终端留给后端）：

# 方式一：走 npm 脚本
cd web
npm run dev

# 方式二：直接跑 Vite（不依赖 npm，等价）
cd web
node node_modules/vite/bin/vite.js --port 5173

# 端口被占用时（常见：上一次的 dev server 没关干净）
#   netstat -ano | findstr "LISTENING" | findstr ":5173 "   → 拿到 PID
#   taskkill /PID <PID> /T /F
排错：页面能打开，但布局全乱 / 所有数据都是空的？
这是 dev server 处于降级状态（配置被批量改写后自动重启只成功了一半）—— 接口代理与 Tailwind 编译都没生效，而且控制台不会有任何报错。 处理：关掉旧进程，重新启动前端。自检：F12 → Network， /api/… 的响应类型应为 application/json（若是 text/html 即为此故障）。

4前后端接入约定

接口基址 /api/v1（VITE_API_BASE，见 web/.env）—— 相对路径，浏览器只看到同源
代理规则 /api 与 /health → http://127.0.0.1:8000，配置在 web/vite.config.ts
鉴权 Authorization: Bearer <token>；Token 存 localStorage，401 时统一清空并跳登录
响应信封 { code, message, data }；code === 0 为成功
业务失败 HTTP 200 + body.code（仅 401 类返回真实 401）—— 这是本项目最易误判的口径，详见「后端入口」
游客链路 上传 → 参数 → 执行 → 结果无需登录（数据归属 user_id = 0）； 导出与历史记录才要求登录
